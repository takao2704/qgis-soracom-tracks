# 認証と権限

## 既存CLIの利用

設定済みのSORACOM CLIとプロファイルを使います。秘密情報はCLI側が管理し、プラグインに複製しません。CLIを配置したパスを接続設定で指定できます。

## API認証情報の入力

- 認証キーID／シークレット：必要に応じて短期トークンを更新します。
- APIキー／APIトークン：期限付きの組を使います。期限後は再入力してください。

QGIS認証ストアに暗号化保存し、設定ファイルには参照IDだけを記録します。QGISのマスターパスワードを設定・解除できなければ保存を停止します。平文保存への切り替えはありません。

## 既存SAMでログイン（終了時にログアウト）

オペレーターID・SAMユーザー名・パスワード（設定時はMFAコード）でログインします。そのSAMに付与された権限でAPIへ直接アクセスし、専用SAMや認証キーは作りません。CLIは不要です。

日本・グローバルの各カバレッジで認証します。パスワードは認証処理後に破棄し、期限付きAPIキー／トークンはプロセスのメモリだけで保持します。QGIS認証ストアや設定ファイルには保存しません。トークンの有効期限は1時間で、期限切れの際は再ログインが必要です。

接続設定の「ログアウト」、認証方式の切り替え、プラグインの無効化、QGISの正常終了でセッションを破棄し、`Auth:logout` APIでこのプラグインのトークンを失効させます。他のアプリやブラウザーのセッションは失効させません。通信失敗や異常終了ではサーバー側の失効を確認できない場合がありますが、トークンはディスクに保存せず、期限後は使用できません。次回起動時は必ず再ログインします。

取得済みの地図レイヤーや保存済みの映像ファイルはログアウトしても削除しません。追加取得には再ログインが必要です。

## 専用SAM・認証キーを作成して継続利用

ログイン後、`qgis-tracks-` で始まる専用SAMユーザーを作成します。既存ユーザーの権限は変更しません。権限設定を読み戻して確認してから認証キーを発行し、QGIS認証ストアへ保存します。ログインパスワードは保存しません。

発行先の権限は次のAPIです。全SIM・カメラを対象とし、特定リソースへの制限は設定しません。

- `Subscriber:listSubscribers`
- `DataEntry:getDataEntries`
- `SoraCam:listSoraCamDevices`
- `SoraCam:exportSoraCamDeviceRecordedImage`
- `SoraCam:getSoraCamDeviceExportedImage`
- `SoraCam:exportSoraCamDeviceRecordedVideo`
- `SoraCam:getSoraCamDeviceExportedVideo`
- `OAuth2:authorize`

ログイン元のSAMには専用ユーザーの作成・確認、権限の設定・確認、認証キー発行の管理権限が必要です。発行先にSIM変更・削除やSAM管理の権限は付与しません。既存キーを直接入力した場合はその権限を変更しません。

作成中断時はQGISプロファイル内の `soracom_tracks/provision.json` にある専用SAM名と段階を確認します。発行結果が不明な要求は自動再送しません。画面の案内に従って管理画面で該当する専用SAMを確認し、不要なものを削除してから再実行してください。アプリ内で発行済み・未保存の場合は「保存を再試行」を使います。

プラグイン削除や接続変更で専用SAM・キーを自動削除しません。不要な認証情報はSORACOM管理画面で失効してください。

## 検証範囲

macOSのQGISで、既存SAMログインによる直接API経由のSIM一覧（日本418・グローバル408）、HarvestのRTK・CLAS各99点のインポート、カメラ44台の一覧取得を確認しました（2026-10-28）。この検証ではCLI呼び出しを禁止した状態で実行しています。

同じSAMを使ったAPI単体検証では、キャッシュを使わず2026-10-22 13:47:21〜13:47:35 JSTの動画を新規エクスポート・ダウンロードし、両カバレッジのログアウトAPI成功とメモリ内の認証情報破棄を確認しました。QGISでは地図上の点クリックから13:46:51〜13:47:05 JSTの動画を新規取得し、内蔵プレーヤーが約14秒まで再生することを確認しました。ログアウトボタンの操作後は、直前まで使えたトークンによるSIM一覧要求が両カバレッジで拒否（HTTP 403）されました。再ログイン後のQGIS通常終了でも、両カバレッジのログアウトAPI成功を確認しました。実際にQGISを再起動し、保存した198点のレイヤーが開ける一方で、接続設定は未ログインとなり再ログインが必要なことも確認済みです。

CLI経由の画像・動画の取得・キャッシュ・表示は従来の実環境検証で確認済みです。専用SAM発行はAPIを置き換えた自動テスト、QGIS認証ストアはアダプターによるテストを含みます。専用SAM発行やすべての認証方式を実アカウントで一貫検証したものではありません。
