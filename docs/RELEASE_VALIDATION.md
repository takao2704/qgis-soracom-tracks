## Windows修正版の追加検証（未リリース、2026-10-28）

Windows 11 x64 / QGIS 3.44.15 / Python 3.12.15 / Qt 5.15.13 / PyQt 5.15.11、表示倍率100%で確認しました。専用QGISプロファイルと新規プロジェクトを使い、CLI呼び出しを禁止した直接API経路で既存SAMログイン、両カバレッジのSIM一覧、2台のHarvest取得、点と受信機別の軌跡生成、ソラカメ動画の新規取得を確認しています。GeoPackageとプロジェクトの保存・再読込、両カバレッジの明示ログアウト、新規API取得の拒否、通常終了と未ログインでの再起動も確認しました。

同じ取得済みMP4で、Qt既定のDirectShowは `ResourceError` / `InvalidMedia` と `0x80040266` を記録し、Media Foundationへ切り替えても `Unsupported media, a codec is missing` で失敗しました。VLC 3.0.24 x64では再生できたため、WindowsでQtの再生が失敗した場合にVLC 3をQGISパネルへ埋め込む代替処理を追加しました。VLC本体は別途必要で、プラグインZIPには含みません。

修正後は、実際の地図上の点クリックからQGIS内の映像表示と再生位置の進行を確認しました。14.011秒の動画を4.655秒で一時停止し、停止中に8.225秒へシークしてフレームが変わること、再開後に12秒以降まで進行することを確認しています。ログアウト後のキャッシュ再利用では追加API呼び出しはありません。通常終了後、プロセス環境変数なしでプロファイルのVLC設定だけを使った再起動・再生も成功しました。

QGIS付属Pythonによる自動テストは104件成功、失敗・スキップとも0、終了コード0です。追加テストは代替プレーヤーへの切替、再生・一時停止・シーク・終了処理、進捗通知による再シークの抑止、未ログインでのキャッシュ検索、VLC検出設定を確認します。配布ZIPは22ファイルの許可リスト、CRC、ソースとの一致を検査しています。実データ、座標、映像、認証情報、個人の設定パスは公開成果物に含めません。

標準プラグイン管理画面によるZIP導入は、PC再起動後に利用者が成功を確認しました。再起動前には、対象プラグインを入れていない新規プロファイルでもZIP指定前に管理画面が応答停止しており、その原因は未特定です。

Windowsでは、認証中の通常終了による自動ログアウト、実APIでの静止画取得、カスタム形式の失敗・復帰、任意追加値、形式・時刻基準の切替時の無再取得、100%以外の表示倍率は未検証です。QGIS 4とLinuxの実機検証も残っています。

## PRレビュー後のmacOS回帰確認（未リリース、2026-10-28）

QGIS 3.44.8 / Python 3.12.11 / Qt 5.15.18 / PyQt 5.15.10で106テストが成功し、失敗・スキップ0、終了コード0でした。追加テストでは、動画の長さ変更によるシークの誤発火防止、macOSでVLCへ切り替わらないこと、VLC設定の不正パス拒否・保存・キャンセル・自動検出への復帰を確認しました。VLC設定画面のテストは一時的な設定ファイルを使用しています。

別プロファイルの実QGISを起動し、既存GeoPackageのコピーから198点を読み込み、保存済みのソラカメ実動画を点選択の処理に渡しました。QtのQMediaPlayerで14.009秒の動画を再生し、2.192秒で一時停止、1秒以上の停止位置保持、停止中の8秒へのシーク、再開と終端到達を確認しました。メディアエラーは0です。操作処理はQGIS内の検証スクリプトから呼び出しており、画面上の手動クリックによる確認ではありません。この回帰確認ではCLI・API呼び出しを禁止し、新規のエクスポートは行っていません。

実QGISのパネルタイトルがGNSS Tracks for SORACOMに変わり、macOSではVLC設定ボタンが非表示になることも確認しました。普段のQGISプロジェクト・設定・キャッシュは検証用のものと分けています。

今回追加したVLC設定画面のWindows実機操作、および設定変更後のVLC再生は未検証です。Windowsで先に確認した104テスト・VLC再生の結果と、今回のmacOSでの106テスト・Qt再生の結果は別の検証として扱います。
